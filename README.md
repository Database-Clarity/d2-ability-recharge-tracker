# Destiny 2 Ability Recharge Tracker

A Windows overlay for timing grenade, melee, and class-ability recharge from the visible Destiny 2 HUD. It samples screen pixels only and does not read game memory. Global low-level keyboard and mouse hooks support configurable input bindings; they pass all input through to other applications. Gameplay input is sent only while an explicitly started repeatability test is active and only when Destiny 2 is the foreground application.

## Run

1. Download `D2AbilityTracker-v<version>-Setup.exe` from the [latest release](https://github.com/Database-Clarity/d2-ability-recharge-tracker/releases/latest).
2. Run setup on Windows x64. It installs under your local app-data folder without administrator access. If the .NET 9 Desktop Runtime is missing, setup asks permission, downloads Microsoft's core and desktop runtime archives, verifies their digests, and extracts them into the tracker's local folder; it does not change system-wide .NET installations and never requires a restart. Future tracker updates reuse the local runtime. If a runtime download is declined or fails, setup still finishes and explains how to retry; the app shortcut becomes available once a runtime is installed. These builds are unsigned, so Windows may show an unknown-publisher warning.
3. If you have an older machine-wide version installed under Program Files, this per-user setup installs a separate copy. After confirming the new copy runs, uninstall the old one from Windows Settings to remove its stale shortcut and files.
4. Keep Destiny 2 visible and choose **Auto-detect areas…**. The selector opens a frozen preview zoomed and centered on all three ability areas: orange for grenade, blue for melee, and green for class ability. Select a box or its legend item to adjust it, then choose **Use all three** to save them together. Cancelling leaves existing areas unchanged. Each detected area includes a small margin around the border and bottom line, limited between neighboring slots so areas do not overlap. **Areas ▾ › Select grenade / melee / class ability area…** remains available for individual manual adjustments and offers a display preview if the game is not found. A small strip below each selection is captured automatically.
5. Leave detection on with the ability charged initially so its ready color can be learned. The ability-use flash arms detection, but timing starts on the later bottom-border recharge pulse, excluding the use animation. The blank completion frame or first returning ready fill is confirmed by stable ready color, while its first timestamp is retained as the endpoint. The final measured duration remains visible after completion, in total seconds to two decimal places alongside minutes/seconds (for example, `73.46 s (01:13.46)`). When enough of the fill-up is observed, a separate linear-regression estimate of total recharge time and its uncertainty is shown alongside the measurement. Repeat-test averages use the same duration format.

The overlay is included in desktop/display screen capture. Game-only capture records Destiny 2's own render surface and may not include this separate overlay window; use display capture to record both.

The control window has four tabs: **Tracking** for ability results and solo tracking; **Repeat test** for automated measurement cycles; **History** for saved measurements; and **Settings** for capture, overlay, troubleshooting (HUD recording), and About (version, update checks, changelog). Startup update checks run in the background; only when a newer release exists does an accent **Update to v…** pill appear beside the capture status on every page. **Check for updates** in Settings › About checks manually; failures show **Retry update check** there with the error in its tooltip and never appear on the main screen. Portable builds check too, but open the release page for a replacement ZIP instead of running the installer. The capture status pill remains visible on every page.

An underline marks the active page. The compact main window uses an integrated dark title bar and border with standard drag, minimize, and close behavior. The Tracking page keeps its actions to a minimum: a segmented **Track: All · Grenade · Melee · Class** selector, the ability results, and a bottom bar with the filled **Pause detection** button (F8 by default), a compact **Overlay** switch (F9), **Areas ▾**, and **⋯** (Move overlay, Copy all results, Troubleshooting). The pause and overlay shortcuts are global and work from every page. Until any ability area is set, a first-run card with **Auto-detect areas…**, **Select manually ▾**, and **Guide** replaces the results. Buttons follow three tiers: filled primary, outlined secondary, and borderless links. Buttons, dropdowns, session-name fields, and numeric fields share a consistent height and dark styling; numeric fields use +/− controls instead of legacy spinner arrows while preserving native stepping and keyboard editing. Focused text fields use an accent border. The selection legend highlights the active ability independently of its color.

Pausing preserves each ability's last state and completed result in the control window. An in-progress timer is shown as stopped, not as a completed measurement; resuming starts a fresh detection cycle.

A status pill beside the page navigation shows capture health on every page: green **Detecting** with the capture backend and measured rate, amber **Waiting for game** or **No capture frames**, red only for actual capture failures, and a neutral **Paused** state naming the resume shortcut. Tracking shows at most one banner above the results explaining the current problem (for example **Waiting for Destiny 2 — start the game and keep the HUD visible.**). A failure shared by every tracked ability is reported once in the banner; ability rows then show a muted reason with their last result, and only failures specific to one ability appear in red on its row (full text in the tooltip). If no capture has succeeded for two seconds, rows show **No capture frames** instead of a live ability state; completed results remain available. The overlay likewise shows **Waiting for game** or **No capture frames** instead of a live state, and its paused header names the resume shortcut. Choosing one ability in the **Track** selector marks the other rows as **Skipped**.

The **History** tab shows saved measurements in a taller window, filterable by ability and session. Only completed, event-confirmed results with a captured uncertainty are automatically stored; discarded, warning-bearing, and model-inferred/refined endpoints are excluded. This confirms the observed HUD events, not whether your gameplay setup was correct. Enter a **New session name** and choose **Start session**, take measurements while changing your stats, then select each result and **Save note** (for example, `Grenade stat 5`). New results join the active session automatically; **Assign to active** can add an older result. **View saved session** filters the table; **Use session** makes an existing open session active. **End session** and the new-session field sit beside the active session's name. **Measured ±** and **Regression ±** show each duration with its own uncertainty; header tooltips explain the difference. Sessions and notes are stored in `%AppData%\D2AbilityTracker\measurement-history.json`. Unreadable history is preserved rather than overwritten.

Repeat tests save individual validated cycles plus a **Mean · N** result when every requested cycle passes the same validation gate. The result belongs to the session active when the test started (or Unassigned if none); switching sessions mid-test does not split it. Add notes or assign the mean just like a single measurement. Measured uncertainty combines the average per-cycle timing uncertainty with the standard error from cycle-to-cycle scatter in quadrature: `sqrt(mean(u)^2 + sum((t - mean(t))^2) / (n * (n - 1)))` for `n > 1`; one cycle retains its own uncertainty. The timing floor is not divided by cycle count because capture errors may be shared. This is an uncertainty estimate, not a confidence interval. Regression means use only cycles with validated 10–90% fits and disclose their count in the cell tooltip. Stopped, failed, or partly unvalidated runs do not create a validated mean; their valid individual cycles remain saved.

Use **Add column** in History to create a named metadata column such as `Grenade Stat`, then double-click its cells to edit values. Column definitions are shared across sessions; values belong to individual results, including repeat means, and save alongside notes. **Export CSV…** exports the currently filtered rows, including session names, cycle counts, raw durations and uncertainties in seconds, notes, and custom columns. CSV uses UTF-8 and locale-independent numbers; formula-like text is prefixed with an apostrophe for spreadsheet safety.

The standalone **Repeat test** page also shows the completed mean with aggregated uncertainty and a separate regression line with its fitted-cycle count. Copy icons beside Tracking results (shown on hover or keyboard focus) and Repeat test results copy their full text, including any visually truncated content. The overlay offers the same copy actions while **Move overlay** is enabled; normal operation stays click-through. Disabled buttons retain readable light text on the dark surface.

The selector shows a frozen preview of the Destiny 2 window when it is detected, or the chosen display as a fallback. Auto-detection recognizes the three ability slots together by their square borders, similar sizes, regular spacing, and shared HUD tilt, then isolates each slot. It does not depend on the colored strips, element colors, or ability artwork. An incomplete three-slot pattern is rejected rather than used to guess missing regions. Previously auto-detected selections are refreshed when the picker finds a new pattern; manual selections are preserved. Zoom with the mouse wheel or +/- and pan with right- or middle-drag. Drag a selection to move it, or drag a corner to resize it; the selection is only saved after choosing **Use selection**, either beside the active selection or in the footer. Use **Areas ▾ › Reset areas…** to clear all saved ability regions and select them again; shortcuts are preserved. Each **Select … area…** item shows that area's current size. The illustrated **Selection guide** compares whole-slot and icon-only selections and shows the bottom-border start flash. Regions are saved relative to their display and scaled when its resolution changes (for example, setup at 4K and play at 1080p).

Use **Record HUD** in Settings › Troubleshooting to save a debug recording of the tracked ability areas (all selected slots, or only the solo slot) with a small surrounding margin. Frames come from the tracker's own capture loop, so recording never competes with detection: lossless PNG frames at 60 FPS are written into a ZIP by a background encoder, with `frames.csv` listing each frame's capture time plus the tracker's live state and progress per ability. There is no size or duration limit; recording stops when you click **Stop** on the Tracking recording chip or **Stop recording** in Settings or if less than 1 GB of disk space remains. Recordings are saved automatically to `Documents\D2AbilityTracker\HUD recordings`. **Open recordings folder** opens that folder in Explorer, creating it if needed; after recording, its tooltip identifies the latest file saved during this app launch. Starting a recording resumes detection if it was paused, and the app overlay is hidden during capture so it will not obscure the game HUD.

Use the **Overlay** switch on Tracking, or the global **Show / hide overlay** shortcut (F9 by default when no other shortcut uses it), to toggle the overlay; the choice is remembered across launches.

Choose one or two lines per ability in the overlay settings. Row heights stay fixed for the selected mode and ability labels and values use aligned columns. The overlay is click-through during normal use; enable **Move overlay** (in **⋯** or Settings) to drag it anywhere on the display, then finish move mode to restore click-through behavior. Its position is remembered.

The tracker checks GitHub for a newer release on startup; when one exists, an **Update to v…** pill appears beside the capture status and the Settings › About button becomes **Update to v…**. Every click checks GitHub's latest release again before offering an installer, so a previously found update never locks the app onto an outdated version. Updates skip intermediate versions. The installer download is checked against GitHub's SHA-256 digest, then the tracker closes, installs silently into the same per-user folder, and restarts. Settings and the local .NET runtime are kept. After updating, the app shows release notes for all stable versions newer than your previous version through the installed version. Failed note downloads can be retried without losing that range. **Changelog**, next to the update button in Settings › About, opens pending notes or recent release notes inside the main app, with formatted release headings, emphasis, lists, and clickable web links. **Back** returns to the previous page; no separate changelog window is opened. Startup update checks can be disabled by setting `CheckForUpdatesOnStartup` to `false` in `%AppData%\D2AbilityTracker\settings.json`.

No manual sample calibration is required. The detector learns each slot's ready hue and color from saturated corner patches, without matching ability artwork or assuming a particular element. A ready slot's broad neutral use flash arms detection; after the slot becomes consumed, increased bottom-border thickness starts timing. Thickness is measured per column with local contrast to support the HUD's slant. A background edge underneath an already charged slot or a moving line inside it cannot start another timer. If the start pulse is missed, the app shows a warning rather than substituting the use animation's timestamp. Select and resume detection while abilities are charged; changing the equipped ability/element requires resetting detection to learn its new color.

During charging, a geometric twin of the slot reads the HUD itself rather than a single brightness edge: it locates the slot's top and bottom border ridges and the recharge boundary on both side strips (including the HUD's slight upward slant), and converts the boundary position into calibrated progress. Each cycle feeds a robust linear recharge model (Theil–Sen seed plus trimmed least squares) that rejects outlier readings, bounds where the next boundary may appear, and keeps the original start time through obstructions. When the HUD becomes readable again, the first sample consistent with the model resumes tracking immediately. The start is the bottom-border thickness pulse after the use animation (also armed by the brief blank phase if the use flash is missed at low capture rates). The endpoint is the short fill-luminance dip that precedes the ready color, confirmed by 150 ms of ready color. If that endpoint frame is obscured but the model saw most of the cycle, the endpoint is inferred from the model and labeled "(endpoint inferred)"; if a clean event was seen between captures the model refines it and the result is labeled "(refined)". Each result shows a ± uncertainty. If the start was obscured, the model's zero-progress intercept corrects it. Otherwise, hidden endpoints are discarded with a warning rather than guessed.

The overlay also shows **estimated total recharge time ± uncertainty**, extrapolated from the recharge model once enough of the cycle is observed. Completed cycles show a separate final regression fitted only to samples between **10% and 90% charge**, excluding the start and end portions. Its inverse slope gives the full 0%-100% recharge duration independently of the measured start and endpoint timestamps. Both the 10% and 90% boundaries must have been observed; otherwise no final regression is reported. The live tracking model still uses the whole cycle for recovery and endpoint estimation. In the reference footage live estimates are within about ±0.3 s from 35% progress onward, and always within their stated ± range. Buffs, energy refunds, and other recharge-rate changes make a cycle nonlinear and invalidate predictions; estimates never count as measured results or trigger automatic ability use.

New selections made from the detected game window follow its position and size automatically. Existing display-relative selections can be reselected to enable this. Temporary contrast loss or a temporarily displaced HUD can recover when the signal returns to its capture region before the endpoint. Arbitrary permanent in-game HUD layout changes still require reselection; the app does not scan the entire screen for a replacement icon.

Capture uses DXGI Desktop Duplication when available: each new desktop frame is held for one capture tick and only the HUD crops are copied out of it on the GPU and read back, timestamped with its present time. This is pixel-identical to GDI but takes about 0.2 ms instead of 15–20 ms, so 60–120 Hz is sustained with a few percent CPU. It falls back to GDI BitBlt per display for rotated or HDR (non-BGRA) outputs, before anything has presented, or while duplication is unavailable (e.g. UAC/secure desktop or mode switches), and retries duplication every second. The control window shows the active backend and measured rate. Capture runs on an above-normal-priority worker (its per-tick work is tiny, so it is not starved while the game loads the CPU) with a high-resolution timer, defaults to a 120 Hz target, and can be adjusted from 30 to 240 Hz using **Capture target (Hz)**. The worker rests for at least three times each capture's processing duration, limiting capture duty to 25% rather than issuing catch-up bursts under load. Nearby HUD slots share a capture buffer, but widely separated selections are split. Lower the target if capture affects gameplay.

Click the pause-binding button and press a key to configure the global pause/resume shortcut; Ctrl, Alt, Shift, and Windows modifiers are recorded with it. App shortcuts are keyboard-only, so mouse buttons are ignored while recording one (shortcuts saved by older versions on mouse buttons are removed). Press **Esc** while recording any binding to clear it. Pressing the shortcut never blocks that input from reaching Destiny 2.

Choosing one ability in the **Track** selector tracks only that ability: the other slots are not captured or shown on the overlay, which keeps capture work minimal when testing one ability. Choose **All** to track every ability again; the choice is remembered. Solo does not have a keyboard shortcut; legacy solo bindings are cleared. Starting a repeatability test for another ability while solo is active switches solo to the test ability. **Start / stop shortcut** in the Repeat test page records a binding that starts the configured test or stops an active one, without switching away from Destiny 2. This is distinct from **Ability use input**, which is the gameplay input sent between test cycles. Action buttons show their configured hotkeys. Bindings must be different from each other; shortcut actions are disabled while the selector is open. Input hooks run on their own message-pump thread and queue actions onto the UI, so a UI/capture stall does not block Windows input processing. Each ability's status in the main window always occupies two lines; overlay line count remains separately configurable.

Click the ability-use binding button and press the desired keyboard key, mouse button, or wheel direction (mouse input is allowed here because it is the gameplay input); modifiers are recorded as well. To repeat a recharge measurement, select an ability with a configured HUD region, record its ability-use input, set the cycle count and post-recharge delay, then start the test. Manually use the ability once to begin cycle one. After each confirmed full recharge the overlay records its duration; if more cycles remain, it waits the configured delay and sends the recorded input through Windows `SendInput` only when `destiny2.exe` is in the foreground and the selected HUD region still appears charged. If a menu hides the HUD, the next use waits until gameplay is visible again. The test stops after the requested number of measured recharges, reports their average, and can be stopped early with the Stop test or pause control. Settings are stored locally under `%AppData%\D2AbilityTracker`.

Automatic repeat uses send keyboard scan codes or mouse-button events. **Ability use input** is saved separately for grenade, melee, and class ability; choose an ability in the Repeat test menu to record or review its binding. Existing installs with one shared input migrate that binding to all three abilities. Set **Hold time · s** on the Repeat test page from 0.01 to 30 seconds for abilities that require holding their input; the saved default is 0.12 seconds, long enough for frame-polled input to observe a tap. Wheel bindings remain single impulses. HUD capture continues during the hold, and cooldown confirmation allows the hold duration plus eight seconds. Stopping, pausing, closing the app or losing game focus releases the input promptly. Inputs are sent only after the selected ability is charged and Destiny 2 is foreground; releases are always attempted, even if a send fails. If a repeat reports no new cooldown, check the recorded **Ability use input** against your in-game binding. Windows can block injection into an elevated game: the tracker and game must run at the same privilege level. A successful Windows input submission does not guarantee that the game accepted it; the next HUD cooldown remains the confirmation.

## Development and automatic releases

Install the .NET 9 SDK on Windows and run `dotnet run` from this folder to build from source. Run `dotnet run --project tests\D2AbilityTracker.Tests.csproj --configuration Release` for automated checks.

Append `-- --ui-smoke "<output folder>"` to render all three control-window pages and check that their controls fit. This opens and closes the tracker using local settings and saves PNG screenshots.

Append `-- --capture-benchmark` to that command for a two-second local DXGI and GDI capture-rate and capture-duty measurement on the primary display, including a pixel comparison between both backends. This uses a HUD-sized desktop region, not live-game performance validation.

The reference-video regression can be run with `dotnet run --project tests\D2AbilityTracker.Tests.csproj --configuration Release -- --replay "<video.mp4>" "<output.csv>"` with FFmpeg on PATH. It expects the supplied 581x182, 60 FPS, 9,982-frame cropped recording and ignores the pink bar. One FFmpeg decode feeds several simulated captures: every frame at 60 Hz, decimated 30/20/15 Hz captures with 35% timing jitter and 3% dropped frames (four seeds each), and a 60 Hz run with simulated obstructions (melee mid-cycle, grenade endpoint, class start). It asserts one grenade completion (160.067 s), two melee completions (49.650 s and 49.667 s), one class completion (90.600 s), and an unfinished second class cycle: exact to one frame at 60 Hz, within 50 ms at 15–30 Hz, recovery within 0.5 s after obstruction, and obstructed endpoints/starts within 0.5 s. Total-time estimates from 35% progress are checked against their error bounds. Initial-cycle expectations match independent LosslessCut frame annotations. These are footage-derived observations, not hardcoded gameplay cooldowns; other recordings need their own region and event annotations.

GitHub Actions checks formatting, runs the automated checks, and packages a framework-dependent Windows x64 app using Inno Setup. The small installer downloads .NET only if neither the system nor the app-local Desktop Runtime is present. It verifies both Microsoft archives against their release-metadata SHA-512 digests in CI and their embedded SHA-256 digests at download time, then combines them under `%LocalAppData%\Programs\D2AbilityTracker\.dotnet`. A runtime download or extraction error does not prevent the tracker itself from installing. Updating reuses the app-local runtime; uninstalling removes it along with the app but preserves user settings. Each release also includes a self-contained portable ZIP that needs no install or preinstalled .NET runtime. Extract it to a writable folder and run `D2AbilityTracker.exe`; its `portable.flag` keeps settings and measurement history in that folder so the whole folder can be moved together.

Releases use semantic version tags such as `v0.1.0`; installer filenames include that same version, such as `D2AbilityTracker-v0.1.0-Setup.exe`, and the executable's version metadata matches. Each successful `main` update automatically increments the patch version beyond existing releases in the current major/minor series. Set `VersionPrefix` in `D2AbilityTracker.csproj` to start a new minor or major series when changes warrant it; the initial series is `0.1.0` while live-game behavior is still being refined. Release runs on the same branch are serialized to avoid version collisions. Older bundled-runtime releases remain available.

For notable user-facing changes, add a concise, single-line bullet to `CHANGELOG.md` in the same commit. Releases lead with only bullets added since the previous release tag; remove an entry if its change is reverted before release. Releases without user-facing changes say so. All release notes retain a separate commit-history section and comparison link at the bottom.

The in-app changelog shows changes since the previous installed version after an update; subsequent opens show only the current release. Commit history and comparison links are hidden until **Show commit history** is selected. Older releases remain available on GitHub.

Pull requests produce downloadable workflow artifacts but never releases. You can also run **Build and release** manually from the Actions tab; only runs on `main` publish a release. Repository Actions must be enabled.
